# TrueView AI — Database

MongoDB via Mongoose. Connection string from `MONGO_URI`
(default `mongodb://localhost:27017/trueview` for local development). The server
runs in a resilient offline mode if MongoDB is unreachable (socket session state
remains authoritative in memory) and retries with capped exponential backoff.

Collections: `users`, `sessions`, `alerts`, `reports`.

## 1. `users`

Purpose: accounts, role, registration state, and biometric profiles.

Important fields:

| Field | Type | Notes |
| --- | --- | --- |
| `fullName`, `email` (unique), `phone` | String | identity |
| `password` | String | bcrypt hash; `select: false` — never returned by default |
| `role` | `user` \| `admin` | admin = reviewer authority |
| `status` | `Active` \| `Inactive` \| `Suspended` | |
| `registrationStatus` | `PENDING_FACE_REGISTRATION` → `PENDING_VOICE_REGISTRATION` → `ACTIVE` | gates logins |
| `faceRegistered`, `voiceRegistered`, `faceVerified`, `voiceVerified` | Boolean | |
| `faceEmbeddings` | `[[Number]]` | 128-D SFace vectors; **`select: false`** |
| `voiceEmbeddings` | `[[Number]]` | 192-D ECAPA or 128-D custom; **`select: false`** |
| `voiceModel` | `ecapa-tdnn` \| `custom-acoustic-vector` | honest backend label |
| `faceVerificationAttempts`, `lastFailedFaceVerification`, `voiceVerificationAttempts`, `lastFailedVoiceVerification` | Number/Date | failed-attempt tracking |
| `lastLogin`, `createdAt`, `updatedAt` | Date | |

Sensitive fields: `password`, `faceEmbeddings`, `voiceEmbeddings` — all protected
via `select: false`; embeddings are only read explicitly (`select('+faceEmbeddings')`)
inside authentication controllers and never returned in API responses.

## 2. `sessions`

Purpose: persisted record of monitored sessions (created by the socket engine and
the unified engine logging endpoint).

Key fields: `sessionId` (unique), `userId`, `userEmail`, `userName`, `mode`/`sessionType`
(`EXAM | INTERVIEW | CLASS | MEETING | ONLINE_CLASS | WORKPLACE`), `status`
(`WAITING | DEVICE_CHECK | READY | LIVE | WARNING | SUSPENDING | SUSPENDED | RESUMING | COMPLETED | EXITED | FAILED | ACTIVE`),
`cameraStatus`/`microphoneStatus`, `trustScore`, `warningLimit`, `criticalLimit`,
`suspensionLimit`, `suspensionReason`, `startTime`, `endTime`, `peakRiskScore`,
`totalAlerts`, `criticalAlertsCount`, `phoneDetections`, `distractionCount`,
`gazeDeviations`.

Relationship: one session → many `alerts` (by `sessionId`) → one `report`.

## 3. `alerts`

Purpose: individual monitoring events (AI events, device interruptions, joins/leaves).

Key fields: `eventId` (default generated), `sessionId` (required), `participantId`,
`userEmail`, `userName`, `type` (required), `eventType` (mirrors type), `severity`
(`INFO | LOW | MEDIUM | HIGH | CRITICAL` plus legacy lowercase forms), `confidence`,
`description`, `evidence`, `status` (`OPEN | REVIEWED | DISMISSED | RESOLVED`),
`timestamp`.

Relationship: `sessionId` joins to `sessions`; the report aggregates them.

## 4. `reports`

Purpose: final evidence-based session reports, auto-generated by
`sockets/proctorSocket.js::generateSessionReport` on completion (manual or timer),
or on demand via `POST /api/reports/generate`.

Key fields: `reportId` (unique, `RPT-xxxxxx`), `sessionId`, `userName`, `userEmail`,
`sessionType`, `durationSeconds`, `startTime`, `endTime`, `completedByTimer`,
`overallIntegrityScore` (0–100), `riskLevel` (`NORMAL | MEDIUM_RISK | HIGH_RISK`),
`totalViolations`, per-signal counters (`phoneDetections`, `cameraInterruptions`,
`microphoneInterruptions`, `multipleSpeakerEvents`, `speechEvents`,
`livenessFailures`, `objectDetections`, `gazeEvents`, `behaviourAlerts`,
`suspensionEvents`, `webRtcConnections`, `webRtcDisconnects`), `faceVerified`,
`livenessPassed`, embedded `alerts[]` and `timeline[]`, `status`
(`PASSED | REVIEW_REQUIRED | FLAGGED`).

## Indexes

- `users.email` — unique (schema-level).
- `sessions.sessionId` — unique (schema-level).
- `reports.reportId` — unique (schema-level).
- Alerts are queried by `sessionId` + `timestamp` in the socket engine; a
  compound index on `{ sessionId: 1, timestamp: -1 }` is recommended for large
  deployments (not yet added — listed under FUTURE_WORK).

## Sensitive-data notes

- Biometric vectors never appear in reports, logs, or API responses.
- Report payloads intentionally contain **no** embeddings — only event counts and timelines.
